# Loop Engineering

AI 에이전트에 구축된 **가드레일(Guardrails)과 안전장치를 토대로**, 실제 업무 수행을 위한 추론 및 실행 루프를 설계하여 안전하고 통제된 **자율적 자동화를 구현**하는 기술 분야

---

## 개요

- **가드레일 기반의 자동화**: 하네스 엔지니어링을 통해 검증된 보안 및 입출력 가드레일을 바탕으로 에이전트의 실행 권한을 신뢰하고 대규모 자동화 프로세스를 안전하게 가동함
- **자율 실행 및 모니터링**: 단발성 호출을 넘어 에이전트가 목표를 달성할 때까지 지속적으로 상태를 갱신하며 판단하고 행동하는 순환 과정을 최적화

## 주요 루프 패턴

- **자율 추론-실행 루프 (Reasoning-Acting Loop)**:
  - 구축된 안전 가이드라인 하에서 에이전트가 스스로 `계획 -> 도구 사용 -> 관찰` 단계를 순환하며 목표를 달성하는 구조 (예: ReAct 패턴)
- **인간 참여 루프 (Human-in-the-Loop, HITL)**:
  - 가드레일이 오작동이나 위험 요소를 감지했을 때, 에이전트의 판단을 정지하고 인간의 승인(Approval)이나 개입을 요청하여 통제권을 반환받는 아키텍처
- **자기 성찰 및 자기 교정 루프 (Self-Reflection / Self-Correction Loop)**:
  - 실행 실패 또는 가드레일 경고 발생 시 에이전트 스스로 원인을 분석하고 프롬프트나 행동을 자가 보정하여 재시도하는 루프
- **지속적 학습 피드백 루프 (Optimization Loop)**:
  - 루프 실행 중 발생하는 다양한 상태 데이터와 사용자 피드백을 수집하여 가드레일 규칙을 고도화하고 성능을 지속 개선하는 선순환 구조

## 주요 리스크 제어 요소

- **안전 탈출구 (Fallback/Escape Hatch)**: 루프 내에서 임계치를 초과하는 가드레일 위반이 감지되면 즉시 실행을 중단하고 인간에게 제어권을 반환
- **무한 루프 제어**: 도구 호출이나 에러 수정 동작이 반복되는 상황을 방지하기 위해 최대 반복 횟수(Max Iterations) 설정 및 예외처리 가드레일 적용
- **상태 보존 및 메모리 관리**: 긴 실행 루프 동안 문맥 정보를 효율적으로 요약 및 보존하여 가드레일 판단의 정확성 유지

## 유래 및 기원

- **개념 정립**: 구글의 **애디 오스마니(Addy Osmani)**가 2026년 6월 경 루프 엔지니어링 아키텍처에 대한 상세한 아티클을 기고하며 대중화
- **영향을 준 인물**: 앤트로픽(Anthropic) Claude Code 팀 리드인 **보리스 체르니(Boris Cherny)**와 OpenClaw 개발자인 **피터 스타인버거(Peter Steinberger)** 등 실무 엔지니어들의 '에이전트를 프롬프팅하는 것 대신 안정적인 자율 루프 코드를 작성해야 한다'는 철학에서 파생됨
